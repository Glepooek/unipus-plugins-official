# dotnet-diagnose-triage

> 版本：1.0.0 | 分类：quality

解读已取得的 .NET 取证输出（dump / SOS 输出 / trace 报告 / 崩溃日志），按假设台账消解循环定位根因，产出带出处与强度标注的诊断结论。

## 触发词 / 内部触发条件

这个 dump 说明什么问题、SOS 输出怎么读、!dumpheap 结果分析、!syncblk 死锁判断、!gcroot 根链读法、托管内存泄漏定位、线程池饥饿判断、WPF 窗口关不掉泄漏、崩溃日志异常链、analyze dump output、read SOS output。

## 业务逻辑流程图

```
┌─────────────────────────────────────────┐
│ Step 1: 证据清点                        │
│ 有什么证据/证据类型/运行时（前置校验，  │
│ 命中 evidence-precheck.md 时加载它）    │
└────────────────────┬────────────────────┘
                    ▼
┌─────────────────────────────────────────┐
│ Step 2: 定征象 + 初始化台账 + 路由      │
│ 加载 symptom-hypothesis-map.md 定候选集 │
│ 台账每条假设状态置 `待验`               │
└────────────────────┬────────────────────┘
                    ▼
┌─────────────────────────────────────────┐
│ Step 3: 裁剪 + 自检 + 出结论            │
│ 按 verdict-forms.md 两形态关闭假设      │
│ 四项自检通过后标结论强度、附交接块      │
└─────────────────────────────────────────┘
```

## 产出物数据流

取证输出（dump / SOS 输出 / trace 报告 / 崩溃日志）
  → dotnet-diagnose-triage（假设台账消解循环）
  → 台账（原文） + 带强度标注的结论（已确认/推测/超出覆盖） + 修复方向 anchor + 交接块
  → 人工接手（复核结论、决定是否采纳修复方向、或续用台账进行下一轮）
