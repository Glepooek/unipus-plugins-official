# 安全软件干扰

> 安全软件是宿主进程外部故障的主要来源之一，且是**最难定案的一类**——它的正常工作方式就是干预其他进程。
>
> 本篇按软件类别与行为形态描述，**不点名具体产品**——见领域 `README.md` 的核心约束。

## 本篇的判定难点

安全软件干扰的取证有一个结构性困难：

**能查到"装了什么"，查不到"它拦了什么"。**

系统提供的安全中心接口只登记已注册的安全产品清单，不暴露拦截日志。而拦截行为发生在内核或进程内部，从外部无法观察。

因此本篇的多数结论强度是「推测」，且**必须**依赖 § 4 的间接证据与排除法。

## 1. 检测面

三类可采集的信息，能力递减：

| 检测面 | 能得到 | 得不到 |
|---|---|---|
| **已注册安全产品** | 产品名、状态（启用/过期）、类型（AV/防火墙） | 它的规则、它拦了什么 |
| **防火墙状态** | 三个配置文件各自的开关状态 | 具体规则命中情况 |
| **WFP 过滤器** | 已注册的过滤层与提供者 | 过滤器的判定逻辑 |

### 1.1 已注册安全产品

系统安全中心维护已注册的安全产品清单，这是唯一的官方查询入口。

| 观察 | 判定 | 强度 |
|---|---|---|
| 无注册产品 | 无第三方 AV（可能仅系统自带） | 已确认 |
| 有注册产品且状态为启用 | 该产品正在运行 | 已确认 |
| 产品状态为已过期/已禁用 | 可能仍驻留但不更新规则 | 推测 |

⚠️ **两个覆盖缺口**：

- 企业级 EDR 产品不一定注册到安全中心
- 已卸载产品可能残留驱动或注册项，清单显示不准

因此**清单为空不等于没有安全软件**。须结合模块列表交叉验证，见 § 4.1。

### 1.2 防火墙三配置文件

防火墙按网络位置分三个配置文件，**必须分别判定**：

| 配置文件 | 适用 |
|---|---|
| **域** | 加入域且连接到域控制器时 |
| **专用** | 标记为专用的网络 |
| **公用** | 未标记的网络（默认） |

| 观察 | 判定 | 强度 |
|---|---|---|
| 当前活动配置文件的防火墙关闭 | 该配置下不拦截 | 已确认 |
| 当前活动配置文件的防火墙开启 | 可能拦截，需看规则 | 已确认（开启）｜ 推测（是否拦截） |

⚠️ **只查一个配置文件是常见漏检**——用户切换网络（办公室→家→热点）会改变活动配置文件，故障可能只在特定网络下出现。

### 1.3 WFP 过滤器

Windows 过滤平台承载防火墙与第三方网络过滤。枚举已注册的提供者可以发现**非系统的网络过滤组件**。

| 观察 | 判定 | 强度 |
|---|---|---|
| 仅系统提供者 | 无第三方网络过滤 | 已确认 |
| 存在第三方提供者 | 网络流量经第三方组件 | 已确认（存在）｜ 推测（是否为主因） |

这是判断"网络被安全软件干预"的少数直接证据之一。

## 2. 拦截现象映射

安全软件的四种拦截方式，各自对应不同现象：

| 拦截方式 | 现象 | 与其他成因的区分点 |
|---|---|---|
| **文件隔离 / 删除** | 启动失败、功能缺失、更新失败 | 目标文件确实不存在或被替换 |
| **网络拦截** | 连接超时、部分域名不通 | 网络分层排查在传输层受阻，见 `network-layered-probe.md § 7` |
| **行为拦截（HIPS）** | 特定操作卡死或失败，其余正常 | 现象与具体操作强相关，重启无效 |
| **进程注入监控** | 整体卡顿、启动慢 | 模块列表中存在其安全组件，见 `module-injection.md § 4` |

### 2.1 一个高辨识度的组合

**「功能正常但特定操作必然失败」+「重装无效」+「其他机器正常」** 这个组合强烈指向行为拦截。

理由：代码缺陷通常不会如此确定性地只影响单一操作且跨机器不一致；而 HIPS 规则恰恰是针对特定行为（写注册表、创建进程、访问某目录）触发的。

### 2.2 更新失败的特殊性

自动更新失败是安全软件干扰的高频形态——更新程序的行为（下载可执行文件、替换正在使用的文件、创建进程）几乎命中所有 HIPS 规则模式。

排查更新失败时**应该**优先考虑本篇，优先级高于网络排查。

## 3. 能力与局限

### 3.1 本篇最重要的一条：查不到"它拦了什么"

系统接口只提供**产品清单**，不提供**拦截事件**。

这意味着：

| 想知道 | 能否得到 |
|---|---|
| 装了哪些安全产品 | ✅ 可以（有缺口，见 § 1.1） |
| 防火墙是否开启 | ✅ 可以 |
| 某次连接失败是否被防火墙拦截 | ❌ **不能** |
| 某个文件是否被隔离 | ❌ 不能（需查各产品自己的隔离区） |
| 哪条规则命中了 | ❌ 不能 |

**因此禁止**由「装了安全软件 + 出现故障」推出「安全软件导致故障」——这正是 `rules/03-conclusion-strength.md § 2` 所约束的形态。

### 3.2 各产品的拦截日志在自己的界面里

唯一可靠的确认途径是**查看该安全产品自身的日志或隔离区**。这需要用户操作其安全软件界面，不在诊断工具的能力范围内。

诊断工具**应该**做的是：告知用户"检出安全产品 X 正在运行，若现象为 Y 类型，建议查看 X 的拦截日志"，并给出查看路径的一般性指引。

## 4. 间接证据与排除法

既然无法直接观察拦截，只能靠间接证据。四种手段，按可靠性排序：

### 4.1 模块列表交叉验证

安全软件的防护组件通常注入目标进程。**模块列表中出现其组件 = 它确实在干预本进程**。

这比安全中心清单更可靠——清单可能漏掉 EDR，但注入的模块骗不了人。见 `module-injection.md § 3.1`。

| 观察 | 判定 | 强度 |
|---|---|---|
| 安全中心有清单 + 模块列表有其组件 | 该产品正在干预本进程 | 已确认 |
| 安全中心无清单 + 模块列表有安全类组件 | **存在未注册的安全软件** | 推测 |

### 4.2 时间线比对

安全软件的安装/更新时间 vs 现象出现时间。

⚠️ **注意规则更新**：安全软件的**规则库更新**也会改变行为，且不改变安装时间。用户说"我没装新软件"时，规则库可能已静默更新数十次。

### 4.3 临时禁用验证

**唯一能把结论升级到「已确认」的手段**，但有三个限制：

| 限制 | 说明 |
|---|---|
| 属系统修改 | 不在诊断阶段职责内，须由用户决策执行 |
| 企业环境可能无权 | 见 § 5 |
| 禁用不彻底 | 部分产品禁用后驱动仍加载，需完全卸载才能排除 |

### 4.4 白名单验证

比禁用更安全的验证方式：把宿主程序加入该安全产品的白名单/排除列表，观察现象是否消失。

**这也是首选的处置手段**——见 § 5.1。

## 5. 企业管控环境的特殊性

企业环境中，安全软件的**处置建议可能全部不可执行**。

| 情形 | 影响 |
|---|---|
| 策略由 IT 统一下发 | 用户无权禁用、卸载或改配置 |
| 客户端被锁定 | 界面不提供关闭选项 |
| 卸载需要口令 | 用户不掌握 |
| 白名单需 IT 审批 | 有流程但非即时 |

因此诊断工具在企业环境中的正确定位是：**产出可交给 IT 的证据**，而非给用户可执行的操作建议。

报告**应该**包含：检出的产品与版本、现象描述、支持该关联的间接证据、建议 IT 采取的动作（加白名单/调整规则）。

### 5.1 处置建议排序

| 序 | 处置 | 适用 |
|---|---|---|
| 1 | **加入白名单 / 排除列表** | 首选——保留防护能力，影响面最小 |
| 2 | 调整特定规则 | 需要 IT 权限与具体规则定位 |
| 3 | 临时禁用（仅用于验证） | 验证手段，非长期方案 |
| 4 | 卸载 / 更换产品 | 最后手段 |

> **【官方】依据**：外部工具的官方文档给出的处置指引即为「将应用添加至安全类软件的白名单，或者退出/卸载相关软件」——白名单优先于卸载。见 `reference/aha-doctor-teardown.md § 2.1`。

⚠️ **禁止**建议用户长期关闭安全软件。这以安全换可用性，且诊断工具无权做这个取舍。

## 6. 本篇覆盖边界

### 本篇能判的

| 能判 | 强度 |
|---|---|
| 已注册的安全产品清单与状态 | 已确认（有覆盖缺口） |
| 防火墙三配置文件各自的开关状态 | 已确认 |
| 是否存在第三方 WFP 过滤器 | 已确认 |
| 安全组件是否注入了目标进程 | 已确认 |
| 某安全产品是否为当前现象的主因 | **推测**——除非经 § 4.3/4.4 验证 |

### 本篇不能判的

| 判不了 | 原因 |
|---|---|
| **它拦截了什么** | 系统接口不暴露拦截事件，这是本篇的结构性限制 |
| **哪条规则命中** | 规则逻辑在产品内部 |
| **文件是否被隔离** | 需查各产品自己的隔离区 |
| **未注册到安全中心的产品** | 企业 EDR 常不注册，需靠模块列表间接发现 |
| **某产品是否"有问题"** | 本领域不内置产品评价，见领域 README |
| **规则库何时更新过** | 不对外暴露，但会改变行为 |

|---|---|
